# AI Teacher

AI teacher for underprivileged / rural students: a white-screen "board" where an AI teacher
speaks in the student's own language (vernacular) while notes, images and diagrams appear and
get cleared, like a human teacher. Owner: Alekh Sinha. Design decisions below were agreed in discussion;
re-open them with the user rather than silently changing them.

## Core idea: one lesson timeline
Every mode produces/plays the same format: `Lesson` = narration audio + timed events
(`note`, `image`, `svg`, `equation`, `highlight`, `clear`). Board state is a pure function of
time (`apps/web/src/player/board.ts`), so seek/replay is always consistent.
- Source of truth: `services/api/src/ai_teacher_api/lesson.py` (Pydantic).
- Regenerate JSON Schema: `cd services/api && uv run python -m ai_teacher_api.export_schema`
- TS types in `packages/lesson-schema/lesson.ts` are hand-mirrored: update when lesson.py changes.

## Modes (build order)
1. **Recorded courses**: lessons max 10 min, generated offline, reviewed by a teacher, replayed from static files. (Phase 0-1 done: schema + player + sample lesson)
2. **Teacher tool** (Phase 2, NOT started): teacher uploads a book PDF, picks a chapter, pipeline makes <=10 min lessons grounded ONLY in the chapter text (source ref per segment), teacher edits/regenerates in an editor, then publishes. Human review before publishing is mandatory.
3. **Voice + text doubt chat** (Phase 4): Gemini Live API via backend, with lesson position/text as context; both text and voice input. Per-session cost caps, stay on topic, say "not sure" rather than guess.
4. **Live class** (Phase 5): agent teaches a cohort; ONE agent session broadcast to N students (not one per student); questions go to a queue, answered one at a time. Feature details TO BE DISCUSSED before building.
5. **Teacher dashboard + chat-driven editing agent** (LAST phase, agreed 2026-10-13; see decisions below). Later: multiple voices, talking-head/3D avatar, more languages, teacher analytics.

## Decisions
- Voice: Gemini Live API (audio-only output; it cannot emit images in the same stream). Images are a separate tool call to a Gemini image model. Diagrams/graphs/labelled figures: LLM-written SVG (exact labels, tiny files) sanitised with DOMPurify. Claude cannot generate raster images.
- Board is a simple stack of React elements (framer-motion), NOT tldraw/Excalidraw/canvas.
- Frontend: React + Vite + TS PWA, mobile-first for low-end Android on weak networks (bandwidth/cost matter). No Next.js.
- Backend: FastAPI + Google ADK, Python managed with `uv`. Browser never holds the Gemini key.
- Cost: recorded mode ~free per view (static files); live is per-minute and grows with context. Prefer recorded; cap live.
- Curriculum: start with NCERT, one chapter. Language not chosen yet (Hindi used for the sample). Nonprofit vs business is undecided (affects licensing).
- Differentiator is not the recording (copyable) but interaction, personalisation, reviewed curriculum-aligned content, teacher tooling and distribution/offline.

## Phase 2 decisions (agreed in discussion)
- First test: `docs/source/fecu106.pdf` = NCERT Class 6 Science, Ch. 6 "Materials Around Us" (22 pp, English + a Sanskrit verse). Lessons are generated in **Hindi**; region context for examples = **Bihar, India** (a teacher-editable setting, not hardcoded; avoid rural stereotypes).
- Do NOT reuse textbook figures (students already have the book); generate our own images/SVG.
- Parsing: plain pdfplumber fails here (two-column interleaving, reversed heading, broken Sanskrit glyphs, duplicated spread pages). Use liteparse (`/home/alekh/Projects/doc-handling/liteparse-main`, spatial parse, Markdown, page screenshots, OCR), with a Gemini-vision check on garbled pages. Output `chapter.json` (sections, activities, figures, page refs).
- Pipeline: parse (code) -> plan agent -> script agent (each line carries a source page ref) -> TTS per line (real durations) -> visual agent (timed from audio durations) -> assemble + Pydantic validate -> teacher editor -> publish. Parse/assemble are plain code, not agents.
- Agents: Google ADK (SequentialAgent + tools). Skills as plain SKILL.md-style files: lesson-planning, vernacular-style, local-examples, svg-diagrams. Run locally first, then deploy to **Agent Runtime** and expose through **Agent Gateway with VPC** (user's GCP guidance; not yet verified by me, the docs MCP tool had an invalid API key). Check whether Live API websockets work through the Gateway before Phase 4.
- Each lesson ends with a quiz and a home activity ("observe this at home, submit photo/voice"). Student submissions are evaluated asynchronously by a multimodal model against a planner-written rubric; feedback guides, never blocks progress; teacher can see submissions; avoid faces; consent + minimal storage (DPDP Act); queue offline.

## ADK facts from the official docs (read 2026-10-12)

Docs call the product "Agent Runtime"; the CLI subcommand is still `agent_engine`. Docs pages: adk.dev/deploy/agent-runtime/deploy/. ADK 2.0 (graph workflows, managed agents) exists.
- Agent Gateway modes: egress (Agent-to-Anywhere) and ingress (Client-to-Agent; governs only `query`/`streamQuery`). Bind with SDK `client.runtimes.create(agent=..., config={...agent_gateway_config...})` or Terraform `google_vertex_ai_reasoning_engine`; requires `identity_type=AGENT_IDENTITY` at creation; runtime must be created after 2026-04-29; gateway and runtime in same region; register agent in Agent Registry; grant `roles/iap.egressor`. Egress is default-deny with EXACT hostnames (register standard, regional and `.mtls.` variants): allowlist first or use DRY_RUN, else calls fail with 498. Changing a binding archives revisions. VPC: Agent Gateway connectivity template + PSC network attachment (PRIVATE_RANGES_ONLY or ALL_TRAFFIC). Docs are silent on gRPC/WebSocket support through the gateway: unverified.
- Skills: ADK `SkillToolset` (experimental), agentskills.io layout (`SKILL.md` + references/assets/scripts), `load_skill_from_dir`; skills written for Claude Code load unchanged. Write our planning/vernacular/local-examples skills in this format.
- Live/voice: ADK `runner.run_live()` + `LiveRequestQueue` + `RunConfig` (experimental). Docs do NOT say it runs on Agent Runtime (which exposes query/streamQuery); assume Phase 4 voice needs Cloud Run / own server until verified.

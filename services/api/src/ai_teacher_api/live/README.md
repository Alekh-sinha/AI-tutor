# live — the streaming live class (one teacher, a room of children)
ONE Gemini Live session per room (`gemini-live-2.5-flash`, location `global`, env `LIVE_MODEL`), broadcast to N children over WebSockets. Not one agent per child.
- `room.py`: pure room logic. Members, hand-raise queue, the FLOOR (only the child who holds it is heard by the teacher; the floor goes to the next hand when the teacher finishes a turn; a solo child always has it; an unused floor expires after 25 s).
- `session.py`: the Live connection. Mic audio in (16 kHz PCM, floor holder only) -> teacher voice out (24 kHz PCM, to everyone) + captions (output transcription) + what the child said (input transcription) + tool calls + `interrupted` (barge-in) + `turn_complete` (floor handover). Reconnects with a session-resumption handle (up to 3 times), 25-minute cap per class.
- `tools.py`: the teacher's tools = the tutor's board tools + `prepare_class` (topic -> class notes with Google Search, 20-60 s, the teacher says she is preparing) + non-blocking `draw_picture`.
- `prompt.py`: short system instruction (rules that can be checked are in code). `routes.py`: `POST /live/rooms`, `GET /live/rooms/{code}`, `WS /live/ws/{code}?name=&key=` (protocol in the file docstring).
- Web: `apps/web/src/live/` (`LiveEntry` create/join, `LiveRoom` screen, `useLiveRoom` socket + mic, `audio.ts` PCM player/mic streamer). Entry points: home "🎓 लाइव क्लास शुरू करें", "🔑 कक्षा में जुड़ें", and the lesson cards.
Logs: `logs/live.jsonl` (`room-created`, `join`, `start`, `connected`, `tool`, `teacher-turn` (what she said + seconds), `interrupted`, `hand`, `floor`, `floor-timeout`, `session-error`, `go-away`, `leave`, `room-closed`). `GET /debug/logs/live`.
Symptom -> look here: "no voice" -> `connected`/`session-error`, and the browser's unlock button (audio needs a tap); "teacher does not hear me" -> `floor` (who holds it), `floor-done` audio_seconds; "stuck/silent" -> `teacher-turn`, `floor-timeout`; "picture never appears" -> `draw-picture-done`.
Known limits: 24 kHz PCM is ~380 kbit/s per listener (heavy for weak mobile networks: needs a codec or lower rate); rooms live in one API process's memory (no restart safety, no multi-server); the host must type the topic or the teacher asks the children (voice answers then go through the floor); reconnect/resumption code is untested against a real disconnect.
Tests: `tests/live/` (room rules), `tests/e2e/live_smoke.py` (real Live API, two clients, synthesized Hindi child speech), `tests/e2e/live_ui_smoke.py` (two browsers).

## Fixes after the first real test (2026-10-15)
Symptoms: the caption showed the whole text but the voice said a few words; the teacher asked a question and answered it herself.
Causes found in `logs/live.jsonl` (`interrupted` with empty `said`, 21 s monologue): (1) a solo child's microphone was always open, so the loudspeaker echo of the teacher's own question was heard as a child's answer and interrupted her;
(2) captions are shown as they arrive, but the model talks faster than real time, so the text is far ahead of the audio and an interruption leaves the unspoken text on screen.
Rules now (code, not prompt): `Room.mic_open` = the child holds the floor AND the teacher is silent (or the child pressed "✋ बीच में बोलना है", event `barge`); the client also keeps the microphone silent while teacher audio is still playing;
captions are queued until the audio clock reaches them and are dropped on `interrupted`; VAD start/end sensitivity LOW; a turn that ends without a question is continued automatically (max 3 in a row, `auto-continue` log);
`self-answer-suspect` is logged when a turn contains a question followed by "सही/बिल्कुल…". Prompt: draw a picture per step when no lesson picture fits. Tests: `tests/live/test_room.py`, `tests/e2e/live_silence.py` (echo simulation against the real Live API, 6/6).

## Redesign after the second real test (2026-10-15): the speech model only talks
Findings: (1) MEASURED: with a tool call in the middle of her speech the audio carries ~8 words/s of transcript (3.0 is normal): more than half of the sentences are dropped from the audio while captions still show them.
A tool call BEFORE speaking is harmless. (2) The speech model praised wrong/garbled answers ("co-deni" -> "बिल्कुल सही जवाब"). (3) Board items piled up and ran ahead of the voice (the model generates ~4x faster than real time).
New design (files): `board.py` — after each teacher turn a text model reads the transcript and decides the board (notes, lesson picture / new picture, new scene, plan, class finished); every op is tagged with `turn` + `at_char`, the client shows it when the audio
clock reaches that character. `hear.py` — the child's microphone is NOT sent to the speech model: the server cuts utterances (energy VAD / done button), transcribes them (text model), `judge.py` checks the answer against the open question and the class notes
(`answer.py`), and the teacher receives text: the words + the verdict. Her only tool is `prepare_class`. Client: one timeline queue (captions, board, turn ends) played against the audio clock; one scene on screen (picture on top, <= 4 notes), subtitle = last 2 sentences.
`finished` state (recap + invitation done): banner "क्लास पूरी हुई — बात कीजिए". Barge-in discards the rest of her current turn (`Room.discard`).
Tests: `tests/live/test_hear.py`, `test_board.py`, `test_room.py`; `tests/e2e/live_answer.py` (real Live API: words per audio second <= 4.5, wrong typed answer judged, no board tools by the speech model) and `live_silence.py`.
Not tested: real microphones (the energy VAD thresholds are guesses: `hear.py` MIN_THRESHOLD / END_SILENCE_S), phones, many children.

## CURRENT DESIGN (2026-10-15, evening): one agent on `gemini-3.8-live` — supersedes the "speech model only talks" redesign above
Why: `tests/e2e/live_diagnose.py` (Langfuse-traced, per-pass WAVs in `logs/diagnose/`) proved that the old `gemini-live-2.5-flash` (half-cascade: it writes TEXT first, a speech step makes the sound) loses the voice of sentences still waiting for
speech when it makes a tool call (audio stopped mid-word at the call; 7 of 12 sentences never voiced; not an SDK, chunk or browser problem). `gemini-3.8-live` and `gemini-live-2.5-flash-native-audio` (both native audio) do not (6/6 and 10/10 sentences voiced) and
send audio at about real-time pace, so a tool call arrives at the point of the speech it belongs to. Both work in this project at `us-central1` (NOT `global`); `LIVE_MODEL` / `LIVE_LOCATION` in settings. 2.5 native audio retires 2026-12-13, so 3.8 is the choice.
Now: the model hears the child's microphone directly (gated in room.py: floor holder + teacher silent, or barge-in button, or "🎧 headphones" duplex toggle) and has the board tools again. Tool calls run as background tasks (`session._run_tool`):
BLOCKING = prepare_class, plan, check_answer (the model waits, then goes on speaking); NON_BLOCKING + scheduling SILENT = write_on_board, show_lesson_picture, clear_board, draw_picture, finish_class (she keeps talking). `draw_picture` puts a pulsing
"🎨 चित्र बन रहा है…" card (note style `pending`) on the board at once and replaces it when the image is ready (events tagged `late`: shown immediately, everything else when the audio clock reaches it).
Safety nets in code: (1) `_watch_idle` tells her to go on after real silence (1.5 s after a tools-only turn, 4 s at the start, 7 s otherwise; never after a question, max 3 in a row; an earlier immediate "go on" interrupted her own continuation);
(2) `_verify_answer`: when a child answered the open question and she starts replying without having called check_answer, `judge.py` judges the answer in parallel; if it is not correct and she already praised it she is cut off and told to correct herself
(log `answer-praised-wrongly`). Observed 2026-10-15: she sometimes calls tools before speaking and ends the turn silently (handled by (1)), and sometimes praises an irrelevant answer without calling check_answer (handled by (2); not yet seen firing in a test).
Kept but NOT wired (for the text+TTS fallback or reuse): `board.py` (text-model board assistant), `hear.py` (energy VAD + transcription), `answer.py`. Fallback plan if this misbehaves: text agent with a `say` tool + Chirp3 voice per sentence, queue played in order.
Cost (list price, unverified bill): audio in $3 / out $12 per 1M tokens (25 tokens/s), text $0.75 / $4.50: about $0.30-0.50 per 20-minute class, one session for the whole room.
Tests: `tests/e2e/live_answer.py` (real API: typed wrong answer, voice ratio, tools), `live_smoke.py` (2 clients + synthesized child speech), `live_ui_smoke.py` (browsers, 9/9; the "board gets an item" step is flaky because the model sometimes delays its board calls), `live_diagnose.py [--model --location --nonblocking --no-tools]`.
NOTE: `npx tsc --noEmit -p .` in apps/web checks NOTHING (root tsconfig only has references): use `npx tsc -b`.

## Third real test (2026-10-15 night): why she stopped, ambient noise, pictures, UI — what changed
Evidence in `logs/live.jsonl` (room 56745): (1) she stalled after tools-only turns until "आगे बढ़िए" was pressed (no `auto-continue` events at all): `_watch_idle` waited for `room.last_child_audio`, which routes.py refreshed on EVERY microphone
chunk, and the always-open microphone streams constantly — so the idle watcher never fired. Now `last_child_audio` = a child's transcript arrived / typed text / pressed speak. (2) the open microphone took side talk as the child ("नहीं, नहीं, नहीं, प्रियंका") and she answered it
("any questions?"); a bare "नहीं।" was even verified "correct". Fix: PUSH-TO-TALK (`Room.talking`, `Room.mic_open`): the microphone is heard only after the child presses "🎤 बोलिए" (this also stops her voice at once) and until "✔ बोल दिया"; typing works any time.
(3) Pictures are no longer drawn during the class (they were late and she then stalled): PLANNING STAGE `prepare.py` — class notes (Google Search) -> a picture plan (text model, <= 6 still photographs) -> pictures drawn one after the other into
`apps/web/public/chat/class-<code>/` BEFORE the Live session starts (children see "चित्र बन रहे हैं… k/n"); the teacher only pulls them with `show_lesson_picture`; `draw_picture` was removed. Measured: notes 34 s + 4 pictures ~2 min = class starts after ~2m50s.
No-topic classes (the children say it by voice): the `prepare_class` tool does the same blocking planning. A running dashboard job holds the image lock: then the class is taught without pictures (log `class-pictures-skipped`).
(4) UI: the board takes all the free height (616 px of 860 in the test), the teacher avatar is a small badge on its corner, the subtitle is the current sentence only at 15 px, the plan is a row of chips, one big "🎤 बोलिए" button.
Tests: `live_answer.py` (topic class: planning, wrong typed answer, voice ratio, ready picture pulled) all passed; `live_ui_smoke.py` 12/12 (mic closed until speak, board >= 35% of the screen).
Not tested: a real microphone with push-to-talk, a phone screen, how the wait of ~3 minutes feels, many children.

## Pictures: parallel planning on two models + a rare fallback (2026-10-15 night, user: "live classes need 4-5 images, can wait up to 10 minutes, keep a new-image tool for questions the pictures do not cover")
Quota facts (gcloud + console + tests): image generation is limited PER BASE MODEL, 2 requests/minute by default, separately for the `global` endpoint (system limit, NOT adjustable) and per region (the `us-central1`/`gemini-experimental` row is adjustable in the console).
`gemini-3.1-flash-image` exists only at `global`; `gemini-2.5-flash-image` (retires 2027-03-15) works at us-central1/us-east4; Imagen and `gemini-3-pro-image-preview` are 404 here. The buckets are independent (tested), so two models = ~4/minute.
`common/picturegen.py`: reentrant (no global state, NO workspace lock any more for classes: a running dashboard job no longer removes the class pictures), pool of the two models with a per-model sliding-window limiter, a 429 blocks that model for 30 s and the other is used.
`prepare.py`: 4-5 pictures planned, drawn in parallel, wait at most `PREP_BUDGET_S`=600 s, the class starts with what is ready. Measured: notes+plan 28 s, 4 pictures finished within 15 s (2 per model, no 429), class started at 43 s (was ~167 s one by one).
`draw_picture` is back as a RARE FALLBACK tool (NON_BLOCKING, SILENT; max 3 per class, `Room.drawn`): placeholder card "🎨 चित्र बन रहा है…", then the picture (events tagged `late`); tested: request at ~110 s, picture at 123 s. Tests: `tests/common/test_picturegen.py`, `tests/e2e/live_answer.py`.
Console quota: raise only the adjustable row ("per minute per region per base_model", region us-central1); after approval re-test with parallel calls to gemini-2.5-flash-image.

## Round 4 (2026-10-16): the kit, the teacher can SEE the board, pacing without button presses
User's test: she paused unnecessarily, asked a question every two sentences, the screen was blank. Evidence (room 72992): turns of 23 words ending in a question; the board tools were called ~2 times per 3 minutes; she cleared the board before each question; prepared pictures stayed unused; one auto-continue
fired 2 s after a tools-only turn and "interrupted" her 0.6 s into speech. User's analysis (adopted): the agent does not know what is on the screen; drawing = prepared material, voice agent only pulls; no scripting of her teaching.
- **Kit** (`prepare.plan_kit`, planning stage): the planner makes steps + ~4 photos + 7-8 HTML FIGURES; counts and "every step has a visual" are checked in code (`kit_problems`, one retry). Figures are written by a text model in parallel with the photos (`figures.py`; 16-22 s each, no image quota),
  checked by `figures.check_html` (tag/attribute allowlist, no script/img/url()/@import/position:fixed, must contain Hindi, <= 7000 chars; rejected figures are re-asked once, else dropped). Tool `show_figure(name)` puts one on the board. Spike (`tests/e2e/html_spike_*.py`): 5/6 look right at 360 px, objects from emoji look crude (so objects stay photos), English words sometimes leak into titles (accepted by the user).
  Client: `live/Figure.tsx` = DOMPurify second pass + Shadow DOM (its <style> cannot touch the page).
- **She can see the board** (`boardstate.py`): every tool answer carries `board_now` ("Board now: EMPTY" / items; "Prepared, not shown yet: ..."), and after every turn of hers the same line is added to her context with `send_client_content(turn_complete=False)` (log `board-status`; works on gemini-3.8-live, no spurious reply seen).
  Status only, no timings, no commands. The server board IS the children's screen now (the client no longer hides things by "scene"): at most 2 pictures/figures and 4 notes, oldest fade (`Turn.max_notes/max_visuals`, `tutor.agent._board`).
- **Pacing** (`session._watch_idle`): no more 1.5/4/7 s waits and no cap. After her turn, once her audio has been PLAYED (estimated from the bytes sent: `play_end`) plus `CONTINUE_GAP`=0.8 s of quiet and nobody pressing speak: "go on". After a QUESTION: wait `QUESTION_WAIT`=15 s for a child (push-to-talk/typing), then ONE message
  "no answer: hint or say the answer yourself and go on" (never at once, she would answer her own question). Never while a child talks, a tool runs, or after finish_class. `interrupted` events now log `since_nudge`, `talking`, `since_child_audio` to find out what interrupts her.
- **Prompt** shortened (~3 KB): a step = one whole explanation of 8-12 sentences, ONE check question per step at its end, board rules (never empty while talking, keep the question's picture, clear only for a new idea).
- **Measured** (`tests/e2e/live_flow.py friction 330`, real API, nobody pressing anything, QUESTION_WAIT was 10 s then): planning 60 s (4 photos + 8 figures); 7 spoken turns, median 62 words (before: ~23), 3 of 7 ended with a question and each got a no-answer hint, 8 auto-continues after tools-only turns, 0 interruptions, 4 photos + 4 figures + 3 notes shown, board EMPTY only for ~2 s after each clear_board.
  The class (4 steps) was over in ~4.5 minutes: steps are short, a 20-minute class needs more steps/depth (not decided). Browser: `live_ui_smoke.py` 12/12, `live_ui_figure.py` (figure rendered in the shadow DOM on the board, no JS errors; screenshot looked right).
- Not tested: real microphone/phone, whether 15 s is enough thinking time for a child, how figures look on very small phones, the figures' science correctness (the writer can state something wrong; nobody reviews them in a live class).
Tests: `tests/live/test_figures.py`, `test_boardstate.py`.

## Round 5 (2026-10-16 night): one screen at a time, catalog, separate question tool, resource-maker planner
User's analysis after round 4 (log room 95765): she put things on the board at the end of her turn, the first screen came after 14-26 s of speech, HTML figures overlapped/cut the old screen, the start/continue messages were English and she switched to English once, a rhetorical "?" mid-turn made her wait 15 s.
Findings by reading the prompt: no board line at the start, no "purpose of the board / show first, then explain", a rule "say your first sentence before any tool" that pushed the board late, a catalog with only 4-word captions (she chose blind), conflicting board rules.
- **Prompt** (`prompt.py`): persona (a teacher at a blackboard: show/write first, then explain; eyes and ears together), no topic-specific words. Host messages (start, continue, no-answer, auto-continue) are in HINDI and every one starts with "BOARD NOW: ..." (`Room.board_status`). The start message makes her first action `plan` then `show_screen`, then she greets: measured, the first screen now appears 4 s after the start, before any speech.
- **Tools** (`tools.py`): `show_screen(heading, picture, figure, notes)` REPLACES the whole screen (event `board op=set`; the server board IS the children's screen; notes that repeat the heading/caption are dropped, at most 4 notes, 2 with a figure). `ask_question(question, expected_answer)` opens a question: the system waits for a child (banner "❓ ..." on every child's screen) and `check_answer()` uses the stored question/expected answer.
  If she asks without the tool the last sentence ending in "?" counts (log `question-without-tool`). Old write_on_board/show_lesson_picture/show_figure/clear_board are no longer offered to her. `draw_picture` and `draw_html` are rare fallbacks (max 3 each): they do not touch the screen; she is told when the item is ready and shows it with show_screen.
- **Planner = resource maker** (`prepare.PLANNER`): its job is pictures/figures that carry the teacher's story BY THEMSELVES: every item has an `intent` (the one thing a child should understand), pictures show one frozen moment with cause and visible effect (no objects merely standing), no subject-specific examples in the prompt (the old prompt had a friction example that biased every topic). 5 pictures + 7-8 figures. Live pictures are ILLUSTRATIONS (`LIVE_STYLE`, user: cartoon is fine for the live class; recorded lessons keep photographs).
- **Vision check** (`prepare.refine_pictures`): a vision model looks at each drawn picture: what it REALLY shows, does it carry the intent, what to point out; a picture that does not communicate is redrawn once from the checker's better description and checked again; if it still fails it is DROPPED (never offered). The catalog (`catalog_text`) in her instruction = what each picture really shows | idea | what to point out; figures: their labels/layout | idea. She does not see the images themselves (user: only if this is not enough).
- **Fixes found by looking at screenshots/logs**: (1) the picture area was blank (CSS selected a `.fx` wrapper that exists only while an effect plays); (2) after the 15 s hint the question stayed marked open and the idle watcher never fired again (4.5 minutes of silence): now `idle_action()` is a pure function with tests, the hint closes the question (kept as `room.last_question`); (3) the board is a column: heading, then ONE picture/figure that takes the room left (figures are scaled down to fit, never cut), then notes; compact controls; figure captions hidden.
- **Measured** (`tests/e2e/live_ui_class.py`, 390x760 browser, real API, nobody answering): planning 2.5-3.5 min (5 pictures + 8 figures + checks + redraws); first screen before speech; 7 screens in 3.6 minutes, never clipped; 4 of 5 questions through ask_question; class finished by itself. By eye: pictures of the marble/ball stopping on mud vs cement, the boy and the ball were good; the match/cooking picture was weakly related; figures are legible but read like label cards (small when 4 notes crowd them: now max 2 notes with a figure).
  Two of five pictures were dropped by the check in each run (the image model often draws something else for abstract processes; the clouds-and-rain topic dropped the evaporation pictures). The class is short (4 steps ~ 3.6 min).
- Not tested: real microphone/phone, children answering (all questions timed out into the hint), 15 s as thinking time, the ADK engine, `draw_html`/`draw_picture` in the new form, a recorded-lesson room with show_screen.
Tests: `tests/live/test_tools.py`, `test_idle.py`, `test_figures.py`, `test_boardstate.py`; e2e: `live_kit.py` (planning only + what each picture really shows), `live_ui_class.py` (screens + speech), `live_flow.py`.
